# Telegram personas in Codex and Claude Code

The achiOS persona pack installs 12 named agents for use from any repository.
Each agent has a core prompt and suggested skills. It can discover and invoke
other installed skills when they fit the request.

| Name | Role |
| --- | --- |
| asa | Thought partner, planning and coordination |
| aea | Coding and ticket implementation |
| luna | Diff and specification review |
| aurora | Architecture review |
| atlas | Infrastructure, services and recovery |
| ari | Research and synthesis |
| ara | Writing in Aki's voice |
| sciel | Vault keeper, chooses the vault from context |
| schoolmem | Sciel for DLSU coursework and schoolMem |
| achimem | Sciel for personal knowledge and achiMem |
| sophie | Thesis engineering and experiments |
| asta | Training and nutrition coaching |

These are portable adaptations of the achiCore personas and Sciel mixin.
The editable prompt bodies live in `agents/<name>.md`; descriptions and suggested
skills live in `config/portable-agents.json`. The installer reads both. Changes
to the Telegram source prompts do not automatically change this pack.

The exported definitions have no tool allowlist, skill allowlist, filesystem
restriction, permission-mode override or Telegram transport instructions.
The client's existing permissions and the current repository's instructions
still apply. Existing services retain their own data and authorization rules.

## Install and update

Use Python 3.11 or newer. On the Mac, Homebrew Python is available at
`/opt/homebrew/bin/python3`.

```bash
cd ~/Code/GitHub/AIS-OS
git pull --ff-only
python3 scripts/install_portable_skills.py
python3 scripts/install_portable_agents.py --dry-run
python3 scripts/install_portable_agents.py
```

The agent installer writes personal Codex TOML files to `~/.codex/agents/` and
Claude Code Markdown files to `~/.claude/agents/`. It checks every destination
before writing. An unrelated file or symlink with the same name stops the whole
install. Repeated installs update only files marked as generated by this
installer. Changed files and the Codex config get unique `.achios-*.bak`
backups beside them. Keep personal prompt edits in the achiOS source files,
because a later install replaces generated copies.

Use `--target codex` or `--target claude` to update only one client. Pulling
the repo updates source prompts; rerun the installer to update native copies.
Start a new CLI session or desktop chat after installation.

The service skills use existing credentials on each machine. Installing a
persona does not transfer credentials, conversation history, vaults or service
databases. See the [portable skills guide](http://100.106.210.38:8999/Code/GitHub/AIS-OS/docs/portable-skills.md)
for Google account selection and server-backed reads.

## Models and invocation

Codex uses `gpt-6.1-sol` with medium reasoning effort as its default for spawned
agents. The installer sets only `agents.default_subagent_model` and
`agents.default_subagent_reasoning_effort` in `~/.codex/config.toml`. These
defaults also apply to other spawned agents that have no model override. The
main session's model and effort remain as configured.

The persona TOML files omit model and effort so explicit spawn choices can
override the defaults. A file that pins a model would take precedence over an
explicit spawn choice, according to the [Codex subagent documentation](https://learn.chatgpt.com/docs/agent-configuration/subagents).
An explicit model choice without an explicit effort uses that model's default
effort. Name both when you want a particular combination.

Claude Code definitions default to `claude-sonnet-5-5` with high effort.
Explicit invocation choices can override the agent's defaults. The exact ID
comes from [Anthropic's model catalog](https://platform.claude.com/docs/en/models/overview).
The [Claude Code subagent guide](https://code.claude.com/docs/en/sub-agents)
describes user agent discovery and invocation precedence.

Examples in either client:

```text
Use Aea to fix this issue and verify the change.
Use Luna to review this pull request against its issue.
Use schoolmem to read this Google Docs link with my DLSU account.
Use Ara to draft this email in my voice.
```

To request a different model, name it and the effort with the agent request.
Codex can spawn `agent_type="aea"` with explicit model and reasoning-effort
values. Claude Code can also use a persona as the main session:

```bash
claude --agent ara
claude --agent ara --model claude-opus-5-5 --effort high
```

Availability depends on the client's authenticated account. Installation and
configuration checks do not prove an inference request succeeds on that account.
Asta's service and Sophie's GPU connection must be available on the host or
reachable through an established remote connection before their tools can run.

## Verification

The regression tests cover prompt export, open skill access, native file
parsing, default settings, config preservation, conflict preflight, backups,
dry runs and repeat installs:

```bash
python3 -m pytest tests/test_portable_agents.py -q
```

For Claude Code, the initialization control response lists discovered agents
and their selected model without submitting a model turn. For Codex, the
app-server `config/read` response reports the two subagent defaults. TOML
parsing verifies the native definitions. Full model turns and specialist
service workflows need separate live checks.

Verified on 2026-10-01 on achibuntu and achibook-air. All 12 native Codex files
parsed, both app-servers reported Sol medium defaults, and Claude initialization
discovered all 12 agents with Sonnet 5.5. Agent tests passed on both machines,
26 each. The server's full AIS-OS suite passed, 949 tests and one existing
unknown-marker warning. No inference request was submitted for these checks.
